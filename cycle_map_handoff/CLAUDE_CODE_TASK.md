# CFAL3: Build the Cycle Map section

Task file for Claude Code. Read fully before editing. The visual and interaction
target is `reference/cycle_map_mockup.html` in this folder (open it in a browser);
the approved content ships as `files/CFAL3/Resources/cycle_map.json`. Your job is
the SwiftUI implementation. Do not rewrite, extend, or "improve" the content: it
was authored and approved through the content pipeline, and corrections arrive
later as JSON replacements, never as code edits.

## 0. Repo context and conventions (do not fight these)

- Repo root: this is an iPadOS/iOS SwiftUI app. Xcode project is generated by
  `scripts/generate_xcodeproj.py`; regenerate if you add files and membership
  requires it.
- Design system: `Theme` (accent, cardRadius, hairline, cardFill, success,
  warning, danger) and `CFAL3/Views/Components/DesignComponents.swift`
  (`.cfaCard()`, `StatCard`, `CapsuleBadge`, `ProgressRing`, `MasteryBar`,
  `PrimaryCTA`). Use these; do not invent parallel styles. No stock
  `ProgressView(value:)` anywhere in Views.
- Content loading: bundled JSON resources decode through `ContentLoader`
  (see how `los_master.json` and `study_schedule.json` load). Decode failure
  must log and leave the feature hidden, never crash.
- Sessions: `StudySessionCoordinator.start(questionIDs:mode:filterDescription:)`
  starts a session over explicit question IDs; `SessionRunnerView` is pushed via
  `.navigationDestination(isPresented:)`. Mirror the wiring in
  `CaseDetailView` ("Work this case") exactly.
- Question bank: `question_bank.json` questions carry `candidate_los` (full LOS
  ids like `<reading_id>.a`). `los_master.json` maps areas > readings > los.
- Never use em dashes in any user-facing string. The JSON already complies.

## 2. The view, layer by layer (parity with the mockup)

Single scrolling screen, content capped at `LayoutMetrics.studyReadingMaxWidth`
and centered at regular width. State: `selectedPhase: Int` (default 2, Late
expansion), `selectedAsset: Int?`, `selectedFramework: Int` (default 3, DM
equity), `openMove: Int?`.

- Phase selector: horizontally scrolling capsule chips of the five phase names,
  selected chip filled `Theme.accent` with white text. Pinned feel is fine but
  optional; a plain row at top is acceptable v1.
- Layer 1 card (`.cfaCard()`): "LAYER 1 - BUSINESS CYCLE" caption in accent
  caps (`.caption2.weight(.semibold)`), phase name `.headline`, description
  body text. Below, an HStack: (a) the yield curve drawn with `Path` in a small
  rounded `Theme.subtleFill` box, one curve shape per `curve_kind`
  (`steep`, `flatten`, `flat`, `inverted`, `resteep`); animate the path change
  with `.animation(.snappy, value: selectedPhase)`; label under it from
  `curve_label`. (b) a Taylor box: monospaced-digit formula caption
  "target = r* + \u03c0e + 0.5(\u03c0e - \u03c0*) + 0.5(gap)" then the phase's
  `taylor` string with the bold segment rendered `.semibold` (the JSON keeps it
  as plain text; render the whole line, bolding the percentage is optional).
- Layer 2 card: framework chip row (eight labels from `frameworks_static`),
  one framework shown at a time. The shown card: label + `CapsuleBadge("R2")`,
  formula caption, then the bar rows, then the caption note, then glossary rows
  (term bold-muted left column ~130pt, definition right). Bar row component:
  label (~120pt, secondary), signed capsule bar (accent for positive,
  `Theme.danger` tint for negative, width proportional, cap ~120pt at 22pt per
  unit), trailing value "+2.5%" in tabular numerals; sum row bold above a
  hairline. Values per framework come from `phases[i].frameworks`:
  cash renders two bars (now, avg) plus its note; singer_terhaar computes
  the three bars in code from `singer_terhaar_inputs` and the phase's
  `rf`/`phi` exactly as the mockup does (RF, phi x rho x sigma x SR,
  (1-phi) x sigma x SR) with the inputs caption underneath.
- Layer 3 card: nine asset chips from `assets`, tinted by stance
  (`OW` green soft, `UW` danger soft, `N` gray soft; selected gets a
  currentColor border). Tapping toggles a panel: chain line in accent
  (`asset_chains`), stance sentence + `mechanisms[asset]`, a "Trap:" line with
  the trap word in `Theme.danger` (`asset_traps`), and the italic exam line.
  Include the OW/N/UW legend row.
- Layer 4 card: title "What you do about it" plus the muted explainer line from
  the mockup. Five move cards; collapsed shows name, `CapsuleBadge(reading_tag)`,
  a chevron, and "What: ..." line. Tap expands (only one open at a time) to:
  "Why (from the layers above): why", "In plain English: moves_static[i].plain",
  "This phase: how", a "Worked numbers" box (`Theme.subtleFill`, the `worked`
  string with its \n line breaks), the `terms` glossary rows, the trap line, and
  the exam line. Reading tag chips are buttons: resolve `reading_tag` through
  `reading_links` (tag > reading title) then match the reading in `los_master`
  by exact name to push `StudyReadingDetailView` for it; if unresolvable,
  render the badge non-interactive.
- Practice CTA (`PrimaryCTA`): title "Practice this phase: <name>". Question
  pool: resolve the phase's distinct `reading_tag`s plus R1 and R2 to reading
  ids (same name match), collect LOS ids for those readings from `los_master`,
  then take every bank question whose `candidate_los` intersects that set.
  Start via the coordinator with `filterDescription: "Cycle Map: <phase name>"`
  and push `SessionRunnerView` exactly like `CaseDetailView` does. Disable the
  button with "No matching questions" if the pool is empty (it should never be;
  see acceptance).

## 3. Entry point

On the Study root (both `StudyPlannerView` compact and the areas column of
`StudyPlannerSplitView`), insert a `.cfaCard()` entry between the mastery
header card and the book grid: chart icon in accent, "Cycle Map" `.subheadline`
semibold, caption "Business cycle to CME to assets to portfolio, one phase at a
time." Tapping pushes `CycleMapView` (NavigationLink compact; in the split
view push onto the detail's NavigationStack or present as a push from the
column, whichever the existing navigation supports without restructuring).

## 4. Hard constraints

- Touch nothing outside: the two Study root files (entry card only),

  adding `cycle_map.json`, and no schema changes.
